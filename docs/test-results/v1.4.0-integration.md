# v1.4.0 integration evidence

**Date:** 2026-10-12. **Status:** implemented, unreleased; full release gate incomplete.

Both PRs were adapted additively rather than merged verbatim. The original 30 skill
names, existing helper/reference content, 220 eval cases, and historical proof assets
remain. Three pre-existing recipes were deliberately repaired; all other original
Python recipe blocks remain byte-for-byte equivalent. Official MCP is preferred for
shared capabilities, while ahujasid remains supported and handles legacy-only assets.

## Portability changes

- The shared skill text now describes logical file, shell, image, and MCP operations
  instead of requiring Claude-specific tool names.
- Unsupported `when_to_use` frontmatter moved into each skill body. All 30 skills pass
  Codex's installed `quick_validate.py`, including the 1,024-character description
  limit. Optional `allowed-tools` remains only as a Claude Code advisory.
- The manifest no longer requires Claude Code. The new agent-host guide documents
  Codex `.agents/skills` discovery, `$skill` invocation, TOML MCP examples, and the
  retained Claude Code installation route.

## Executed checks

- **Host tests:** 6/6 passed. They cover manifest/frontmatter contracts, Python
  syntax, 225 eval-case preservation, the three-recipe exception allowlist, original
  resource preservation, bake API layouts, and the reference-helper pipeline.
- **Blender export tests:** 12/12 passed on Blender 5.1.1, including collision geometry,
  names, selection restoration, FBX re-import, real Multires baking, cage export,
  combined collision/cage export, state restoration, UV coverage, and GLB output.
- **Core recipe tests:** the v1.3.0 baseline passed 32/35. The candidate passed
  **35/35 through legacy MCP and 35/35 through official MCP**. The corrected checks
  now also assert layered-action linear keyframes, valid EEVEE configuration, and
  decimation context restoration plus reduced export/re-import geometry.
- **MCP regression comparison:** no candidate-only failures, fixture geometry changes,
  or image differences outside the measured baseline-repeatability envelope. Real
  calls covered execution/stdout, scene/object inspection, screenshots, nested
  errors, official documentation search, and returned render paths.
- **Native Codex:** explicit discovery succeeded from an isolated project-local
  `.agents/skills` installation. A legacy workflow produced and visually verified a
  blue-sphere render and GLB. An official workflow used direct leaf skills to create
  a material, animation, render, passing collision preflight, collision FBX, and an
  animated GLB. The red-cube and blue-sphere 128×128 renders were visually inspected.
  A separate native Multires turn timed out before emitting a usable trace; the same
  helper passed its deterministic real-Blender tests.

The disposable tests used factory-startup Blender, private ports, temporary outputs,
and separate server environments. They did not alter personal MCP configuration or
install the skills into personal directories. Raw traces contain machine-local paths
and remain outside the repository.

## Three compatibility repairs

| Check | Baseline failure on Blender 5.1.1 | Candidate result |
|---|---|---|
| D3: camera orbit | Direct `Action.fcurves` failed on layered actions | Uses both legacy and layered Action layouts; verifies linear keyframes |
| E2: EEVEE preset | Removed `SceneEEVEE.use_gtao` raised an exception | Guards versioned properties and uses supported Fast GI AO where available |
| G4: decimation | Nonexistent `use_collapse_degenerate` raised an exception | Uses the valid modifier API and restores active object, selection, and mode |

## Remaining gates and limits

- **Release gate incomplete:** the 225 trigger queries and ten backend scenarios have
  not been run as native baseline/candidate traces in both supported clients. Claude
  Code is unavailable in this environment. Native Codex workflow evidence is useful
  but does not replace that matrix. `merge_ready` therefore remains `false`.
- **Unverified:** Unreal engine imports and new Blender 4.x/5.2 live behavior. Blender
  FBX export/re-import does not establish Unreal-side collision or material acceptance.
- Provider downloads/generation were preserved but not executed against external
  services. No credentials, paid generation, or network asset calls were used.
- These are bounded correctness checks, not a universal compatibility or aesthetic
  guarantee. No merge, push, publication, or personal installation was performed.
